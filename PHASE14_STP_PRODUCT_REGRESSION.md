# Phase 14 STP and product regression

The campaign planner, economics engine, research dashboard and threshold engine were not restructured. The only live screening changes were conservative OCR transcript selection and a development-supported `limited time only` pressure phrase. No cue weight, tier boundary or 0–10 cap changed.

The post-change full suite ran **110 tests, 0 failures, 0 errors, 0 skips** using the documented R-backed SPSS test adapter and original local secondary files. Existing tests cover the A–E keep/revise/target/test/multiple-variant option comparisons; total budget, committed spend, remaining headroom, costs, cent precision, break-even extra conversions, user-entered hypothetical scenarios, permission and data-source conflicts, and minimum-change preference. These are software tests of arithmetic and rules, not observed conversion uplift. The complete suite includes Phase 11 synthetic fixtures and Phase 12/13 regression checks. Seven Phase 14 methods explicitly test OCR selection, deadline/negation, seller context and five-level abstention, plus one severe-garble guard, making eight new tests.

Actual Playwright automation of installed Google Chrome passed **23/23** checks against `127.0.0.1:8765` (see `phase14_validation/browser_checks.cjs`; local observations are in ignored `phase14_validation/local_results/browser_results_v1.json`). The exercised UI states included clear/small/photographic/angled English image uploads, a synthetic deadline, a genuine Altair deadline upload, seller phone and email, viewer-specific phone claim, negated urgency, quoted tracking instruction, generic and unreadable image, mixed/unsupported-language image, unknown data source and consent, affordable and unaffordable revision, invalid-budget recovery, a hypothetical scenario, generic phone-entry wording, and a 390 px mobile viewport. The real Altair image showed its deadline text, `moderate_intrusive` 2/10 and a revision action. The unreadable and no-cue images abstained or carried review warnings; mobile had no horizontal overflow. These checks verify actual form submission and response display, but do not constitute user research or exhaustive browser/accessibility coverage.

Mode A remains a research-informed pre-launch advisor. Mode B remains offline schema validation only, without customer-file upload. No original saved research model or result was changed. The threshold remains `status: insufficient_evidence`, `recommended_level: None`; an OCR improvement supplies no linked five-level consumer response evidence. Permission unknown and data-source conflict still yield `hold_for_review`. No action predicts conversion uplift, ROAS or profit.
